# Blogger CRM — демо

Упрощённая версия CRM для работы с блогерами, которую я делал для e-commerce бренда:
рекламные кампании, интеграции с промокодами и UTM, продажи с маркетплейсов
и аналитика окупаемости через ДРР — долю рекламных расходов в выручке. Код написан с нуля для портфолио,
все блогеры, товары и цифры выдуманы.

## Что можно потрогать

- **Дашборд** — расходы и выручка по месяцам, ДРР, топ блогеров, тепловая карта «день недели × площадка», доля Ozon / WB / сайта.
- **Кампании, интеграции, блогеры** — списки с фильтрами, поиском по промокоду и сортировкой по ДРР, карточки с историей интеграций, создание кампании и интеграции (промокод генерируется).
- **Отчёты Ozon** — журнал по дням: отчёт за каждый день скачан и разложен по промокодам, видны повторы после ошибок API и разбивка по блогерам. Сегодняшний отчёт воркер докачивает каждые 30 секунд, кнопка «Обновить за сегодня» ставит загрузку в очередь вне расписания.
- **Пользователи и настройки** — сотрудники с ролями и приглашение нового, подключения к площадкам, пороги ДРР.
- **Фоновый воркер** — забирает отчёты Ozon из очереди (асинхронный отчёт с опросом статуса, иногда 429) и заказы сайта, раскладывая продажи по интеграциям. Видно в `docker compose logs -f worker`.

## Запуск

```bash
docker compose up --build
# http://localhost:3000
```

Данные пересоздаются при каждом старте `api` (`DEMO_RESET=true`).

## Устройство

```
браузер ──▶ web (Nuxt 4, SPA + Nitro BFF) ──▶ api (Go) ──▶ PostgreSQL
                                               ▲
                                    worker (Go) ┘  «Ozon» / «CRM»
```

| Часть | Стек |
|---|---|
| `api/` | Go 1.25, `net/http` ServeMux, pgx v5, slog. Домены `blogger`, `campaign`, `analytics`, `ozon`, `user`: model → repository → handler |
| `api/cmd/worker` | тот же модуль, отдельный бинарник; advisory-лок Postgres разводит миграции и сид между процессами |
| `web/` | Nuxt 4 (`ssr: false`), Tailwind 4, Chart.js; `server/api/[...path].ts` проксирует запросы в Go, адрес API не попадает в браузер |

Решения, которые стоит посмотреть:

- агрегаты расходов и выручки считаются отдельными CTE — join интеграций с дневными метриками напрямую размножил бы стоимость;
- сортировка — только по белому списку колонок, в `ORDER BY` не попадает пользовательский ввод;
- отчёты Ozon идут через очередь в Postgres: расписание и кнопка только ставят день в очередь (повторная постановка во время загрузки — 409), воркер забирает его `FOR UPDATE SKIP LOCKED`;
- итоги отчёта в журнале пересчитываются из `integration_metrics`, а не суммируются, поэтому журнал всегда сходится с аналитикой;
- деньги хранятся в целых рублях (`bigint`), без float.

## Разработка без Docker

```bash
cd api && DATABASE_URL=postgres://crm:crm@localhost:5432/crm?sslmode=disable go run ./cmd/api
cd api && go run ./cmd/worker
cd web && npm install && NUXT_API_BASE=http://localhost:8080 npm run dev
cd api && go test ./...
```
