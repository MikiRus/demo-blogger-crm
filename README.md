# Blogger CRM — демо

Упрощённая версия CRM для работы с блогерами, которую я делал для e-commerce бренда:
рекламные кампании, интеграции с промокодами и UTM, продажи с маркетплейсов
и аналитика окупаемости (ДРР, ROAS). Код написан с нуля для портфолио,
все блогеры, товары и цифры выдуманы.

## Что можно потрогать

- **Дашборд** — расходы и выручка по месяцам, ROAS, топ блогеров, тепловая карта «день недели × площадка», доля Ozon / WB / сайта.
- **Кампании и блогеры** — списки с фильтрами и сортировкой, карточки с историей интеграций, создание кампании и интеграции (промокод генерируется).
- **Загрузка отчёта WB** — скачайте пример XLSX, загрузите обратно: превью покажет новые строки, уже загруженные дни, неизвестный промокод и битую строку. Записываются только новые.
- **Фоновый воркер** — каждые 20 секунд «заказывает» отчёт Ozon (асинхронно, с опросом статуса) и забирает заказы сайта, раскладывая продажи по интеграциям. Видно в `docker compose logs -f worker`.

## Запуск

```bash
docker compose up --build
# http://localhost:3000
```

Данные пересоздаются при каждом старте `api` (`DEMO_RESET=true`).

## Устройство

```
браузер ──▶ web (Nuxt 4, SPA + Nitro BFF) ──▶ api (Go) ──▶ PostgreSQL
                                               ▲
                                    worker (Go) ┘  «Ozon» / «CRM»
```

| Часть | Стек |
|---|---|
| `api/` | Go 1.25, `net/http` ServeMux, pgx v5, excelize, slog. Домены `blogger`, `campaign`, `analytics`, `report`: model → repository → handler |
| `api/cmd/worker` | тот же модуль, отдельный бинарник; advisory-лок Postgres разводит миграции и сид между процессами |
| `web/` | Nuxt 4 (`ssr: false`), Tailwind 4, Chart.js; `server/api/[...path].ts` проксирует запросы в Go, адрес API не попадает в браузер |

Решения, которые стоит посмотреть:

- агрегаты расходов и выручки считаются отдельными CTE — join интеграций с дневными метриками напрямую размножил бы стоимость;
- сортировка — только по белому списку колонок, в `ORDER BY` не попадает пользовательский ввод;
- превью отчёта и запись разделены, при записи сервер заново классифицирует строки и не доверяет статусам из браузера; `ON CONFLICT DO NOTHING` страхует от гонки двух загрузок;
- деньги хранятся в целых рублях (`bigint`), без float.

## Разработка без Docker

```bash
cd api && DATABASE_URL=postgres://crm:crm@localhost:5432/crm?sslmode=disable go run ./cmd/api
cd api && go run ./cmd/worker
cd web && npm install && NUXT_API_BASE=http://localhost:8080 npm run dev
cd api && go test ./...
```
